# 網站管理操作說明（給協會工作人員）

所有內容都在「網站公開內容管理表」（Google 試算表）裡改，不用碰程式。改完約 30–60 分鐘網站自動更新（免費 GitHub Pages 版）；急的話可以手動立即更新（見第九節）。

## 一、發布狀態怎麼用

| 狀態 | 網站上會不會出現 | 用途 |
|---|---|---|
| 草稿 | 不會 | 還在寫 |
| 待審核 | 不會 | 等理事長或承辦確認 |
| 已發布 | **會** | 正式公開 |
| 已封存 | 不會 | 下架但保留紀錄（不要直接刪列） |

## 二、新增一場活動（分頁：活動管理）

1. 往下新增一列，**活動ID** 用「年度-日期」，例如 `A116-0418`（只能用英數字和 -）。
2. 必填：年度、活動名稱、活動類型、活動日期（`2027-04-18`）、活動狀態、公開狀態。
3. 活動類型從這 9 種選，可多選用 `|` 分隔：SUP入門體驗、SUP常態訓練、浮潛親海體驗、親子海洋運動、共融及適應性海洋活動、水域安全教育、進階訓練及自由潛水銜接、青年志工、助教及專業培訓、趣味競賽及成果分享。
4. 名額、費用：**有正式資料才填**，沒填網站就不顯示。
5. 報名表單網址：開啟 Google 表單 →「傳送」→ 連結圖示 → 複製（`…/viewform` 或 `forms.gle/…`）。**不要貼編輯網址**，網站會自動擋掉。
6. 活動狀態改成「開放報名」且有報名網址，網站才會出現報名按鈕。
7. 公開狀態改「已發布」。

### 活動異動

把「異動公告類型」改成 調整場地／延期／取消，並在「異動公告」寫說明。網站會在活動頁顯示醒目提醒。
**網站公告不取代 LINE 或電話通知**，重大異動仍要個別通知參與者。

### 活動結束後

1. 活動狀態改「已完成」。
2. 「參與人次」填保險名冊當日人次（數字）；「活動成果」寫一句話（例：保險名冊 59 人次）。
3. 活動頁會保留，變成年度活動回顧；之後可在「活動故事」補一篇故事。

## 三、首頁公告（分頁：網站公告）

類型可選 一般／正常辦理／調整場地／延期／取消。可設定開始、結束顯示日期，過期自動下架；「置頂」填是會排最前面。

## 四、上架照片（分頁：照片與影片）

1. 照片檔請交給網站維護人員放到網站，或使用可公開的圖片網址。
2. **授權狀態**：確認當事人（未成年者為家長）同意公開後才填「已授權」。不同意露臉或授權未完成，填「待確認」或「不公開」。
3. 替代文字（給視障者的圖片描述）必填，例如「學員在外木山海面划 SUP」。
4. 用途可填：首頁主視覺｜主題封面｜年度精選｜故事｜故事封面｜安全教育｜行前準備。
5. 正式網站只顯示「已授權＋已發布」的照片；沒有照片的區塊會改成簡潔設計，不會開天窗。

## 五、寫活動故事（分頁：活動故事）

- 一定要填「活動ID」，連到真實辦理的活動；沒有對應活動的故事不會顯示。
- 只寫實際發生的事。引用參與者心得前，要有原始回饋資料並取得公開同意。
- 段落之間空一行。照片ID清單用 `|` 分隔。

## 六、年度成果與 KPI（分頁：年度KPI）

- 「確認狀態」＝**已列報** 才會公開實績數字與達成率。
- **協會確認達標**：協會確認已達成核定目標、但名冊含個資不公開人數時使用（115 年度的固定會員、青年志工、助教、救生培訓）。網站顯示「達標」，不顯示人數。
- 「待補佐證」「待確認」只顯示目標。日後若要公開人數，填入實績值並改「已列報」。
- 人次 ≠ 人數。報名筆數、問卷份數不要加進年度人次。

## 七、正式表單與 LINE（分頁：公開連結）

- `line_official`：官方 LINE。
- `form_safety_quiz_115` 等表單：確認是填答網址、仍開放填答後，「確認狀態」改已確認、「發布狀態」改已發布，網站才會出現按鈕。
- **新年度請另建新表單**，不要沿用 115 年度表單，以免回覆混在一起。

## 八、新年度

在「年度計畫」新增一列（例如 116），填計畫名稱、補助單位、補助單位 Logo 與標示方式。各分頁「年度」欄填 116，網站自動多出 116 年度成果館。補助單位只會出現在該年度，不會套用到其他年度。

## 八之一、新增照片

1. 照片放進網站儲存庫 `public/media/年度/` 資料夾（例如 `public/media/116/0405-sup-group.jpg`），寬度建議 1600–1920px。
2. 在「照片與影片」分頁新增一列，「檔案路徑或網址」填 `/media/116/0405-sup-group.jpg`，「授權狀態」確認後填「已授權」。
3. 要當首頁或活動封面：「用途」加上 `首頁主視覺`、`主題封面`，或在「活動管理」的「封面照片ID」填照片ID。
4. 維護人員在電腦執行 `python3 scripts/make_image_variants.py` 產生手機用縮小版後推送；沒有執行也能顯示，只是手機會下載原尺寸。

## 九、檢查與立即更新

**免費 GitHub Pages 版（目前採用）**

- 立即更新：登入協會 GitHub → 網站儲存庫 → 上方「Actions」→ 左側「更新並發布網站」→ 右側「Run workflow」→ 綠色按鈕。約 2–3 分鐘後網站更新。
- 檢查資料：同一頁點最新一次執行，往下看「Summary」的「網站內容檢核」，會列出資料來源、格式錯誤、被擋下的列與數據一致性（例如活動人次加總是否等於年度名冊人次）。
- 「資料來源」若顯示「網站內建資料」，代表沒讀到試算表，請確認試算表仍是「知道連結的任何人可檢視」。

**伺服器版（Vercel 等）**

- 檢查頁：`https://網站網址/cms-check?token=通行碼`。
- 立即更新：請維護人員執行 `/api/revalidate`（見 README），或等 5 分鐘。

## 十、絕對不能放進這份試算表的資料

身分證字號、生日、電話、地址、緊急聯絡人、保險名冊、健康狀況、血氧心率等檢測值、原始核銷憑證。
這些資料若誤放，網站會自動拒絕讀取該分頁或隱藏該列，但仍請立即從試算表刪除。
